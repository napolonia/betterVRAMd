llama-server is the primary inference backend.

02.2 BACKEND INTERFACE

 - Common inference backend interface.
 - Common inference result types.
 - Common inference exception types.

02.3 LLAMA.CPP BACKEND

MODULE: vramd/inference/llama_cpp.py

Responsibilities:

 - Build llama-server commands.
 - Validate executable and model paths.
 - Communicate with the running server through HTTP.
 - Provide readiness checks.
 - Handle inference requests.


The backend does not own subprocess creation or termination.

02.4 WORKER PROCESS

MODULE: vramd/worker/process.py

Responsibilities:

 - Create the llama-server subprocess.
 - Own the subprocess lifecycle.
 - Monitor process startup and termination.
 - Handle graceful and forced shutdown.
 - Track the selected server port.

02.5 LIFECYCLE CONTROLLER

MODULE: vramd/core/lifecycle.py

Responsibility:

 Coordinate model loading and unloading.


The controller does not directly own inference subprocess creation.

02.6 INFERENCE SCHEDULER

MODULE: vramd/core/scheduler.py

Responsibility:

 Coordinate inference request scheduling and queue execution.

02.7 ARCHITECTURAL RESTRICTIONS
 - Only one inference worker/server may be active at a time.
 - Only one inference model may be resident at a time.
 - The backend communicates with the running server.
 - WorkerProcess owns the server subprocess.
 - LifecycleController coordinates model lifecycle.
 - InferenceScheduler must respect lifecycle decisions.


Worker and backend integration has not yet been validated.
