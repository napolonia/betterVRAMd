2. ARCHITECTURE DECISIONS
VRAMdManager owns the main application services.
LifecycleController receives registry, cache and metadata inspector through dependency injection.
Model registration never automatically loads models.
Application startup must not warm model pages or allocate GPU resources.
Model caching uses mmap.
No memory locking by default.
GGUF inspection uses the Python tooling bundled with the custom llama.cpp build.
Memory estimates are preliminary and must not be treated as guaranteed capacity.
Resource allocation must account for KV cache and runtime overhead.

See PROJECT_CONTEXT.txt for complete architecture decisions.
