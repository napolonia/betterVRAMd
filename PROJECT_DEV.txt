RAMCacheManager.unload() closes the memory mapping before removing its cache entry.

2. Issues requiring attention
I identified the following important issues.

A. Resource-budget enforcement

LifecycleController.load_model() accepts a GPU-layer count directly.

It does not independently establish that:

A current resource budget exists.

The selected configuration is feasible.

The configured RAM and VRAM limits are respected.

Resource selection currently exists separately in VRAMdManager.

We need to establish a clear loading decision path.

B. Multimodal projector integration

ModelRegistry identifies an associated projector, but:

LifecycleController does not pass mmproj_path to WorkerProcess.start().

The projector is not included in memory estimation.

Projector caching and residency are not coordinated.

C. Unloading failure handling

There is an important issue in unregister_model().

If unloading the cache fails after the worker has stopped, the registry can still unregister the model while its cache entry remains.

We should prevent this inconsistent state.

D. Lifecycle state management

The controller currently tracks only:

Registered.

Cached.

Running.

It needs more explicit handling of transitional and failed operations, particularly when startup cleanup cannot terminate the subprocess.

E. Scheduler integration

The scheduler currently manages requests independently.

It does not yet:

Validate model registration.

Coordinate with the lifecycle controller.

Ensure model residency before dispatch.

Dispatch requests through the active backend.

This is a subsequent integration concern, not something to solve by giving the scheduler subprocess ownership.

F. GPU memory reclamation

The configuration supports verify_memory_release, but there is no implemented verification procedure in the lifecycle.

We should distinguish successful process termination from confirmed GPU memory reclamation.

3. Recommended implementation order
I recommend the following sequence:

Correct LifecycleController resource-aware loading.

Complete model startup and readiness coordination.

Correct unloading and failure cleanup.

Integrate multimodal projector handling.

Integrate lifecycle decisions with VRAMdManager.

Connect scheduler execution to the lifecycle-controlled backend.

No inference or integrated testing is necessary for these implementation changes.
